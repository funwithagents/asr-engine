# Gradio Demo App

**Status:** Done

Implements the settled behavior in `specs/gradio-demo.md` — a direct-import
Gradio example that drives an in-process `ASREngine`. Delivers a UI-agnostic
`DemoController` plus a thin Gradio `app.py` and an optional `demo` dependency
group. As an example it ships **no automated tests**; it deliberately leaves out
browser-mic capture, segmentation-param editing, and per-module field editing
(spec Open questions).

## Steps

1. **Dependency group.** Add `demo = ["gradio"]` under `[dependency-groups]` in
   `pyproject.toml`. Because pyright's `include` now covers `examples/` (which
   imports gradio) and gradio only resolves for pyright when actually installed,
   make `demo` a default sync group: `[tool.uv] default-groups = ["dev", "demo"]`,
   so `uv sync` / `uv run pyright` / Pylance all have gradio. gradio stays out of
   `[project.dependencies]`, so library consumers never pull it.
2. **Engine getter.** Add the read-only `ASREngine.segmentation_mode` property
   (returns `self._segment_mode`) per `specs/engine.md`. Add a `tests/test_engine.py`
   case: set a mode, assert the getter reflects it, and assert it reports the
   always-on mode again after a `listen` in a different mode.
3. **`DemoController` — construction & config.** Build from a base
   `ASREngineConfig`. Implement `available_devices()` (delegates to
   `AudioCapture.list_devices()`), `available_modules()` (`sorted(REGISTRY)`),
   `set_device`/`set_module` (mutate pending config, drop any cached engine,
   raise `RuntimeError` if running). Start a dedicated event loop in a daemon
   thread in `__init__`; add a helper that runs a coroutine on it via
   `run_coroutine_threadsafe(...).result(timeout=...)`.
4. **`DemoController` — engine lifecycle.** Lazily construct the `ASREngine` from
   the pending config on first `start()`/`listen()` after a config change, wiring
   `on_speech_utterance`/`on_speech_segment` to thread-safe buffer appends
   (bounded deques for the logs; store latest separately). Implement `start`,
   `stop`, `listen(mode)` marshaled onto the loop thread. Catch construction /
   start errors (unknown module, unsupported format, missing key) and store them
   in `state().message` instead of propagating.
5. **`DemoController` — segmentation & state.** `set_segmentation_mode` calls the
   engine. Implement `state() -> ControllerState` returning the snapshot from the
   spec's table, sourcing `segmentation_mode` from `engine.segmentation_mode`
   (pending config when there is no live engine), including derived enablement
   flags (stopped / running / listening) and formatted utterance/segment log
   lines (finals only for utterances; closed segments with `end_reason`).
6. **Gradio `app.py`.** Replace the scaffold: `main()` parses `--config` (reuse
   the server's config loader for the `engine` block; fall back to the built-in
   `deepgram_v1` default), builds the `DemoController`, and launches a `Blocks`
   page with the config row, control row (Start/Stop/Listen + seg-mode selector),
   state row, and results panels per the spec. Bind each widget to a controller
   method; drive live refresh and widget enablement from `controller.state()` via
   a `gr.Timer`. Keep all logic in the controller — `app.py` only wires.
7. **Docs & frontmatter.** Update `specs/gradio-demo.md` frontmatter (add
   `controller.py` to `code:`; `tests:` stays empty) and flip its status to
   `Implemented` (file + `specs/_index.md`). Flip `specs/engine.md` back to
   `Implemented` (file + `specs/_index.md`) now that the getter exists. (The
   `examples/` row in `AGENTS.md` and both `_index.md` rows were added when the
   specs were authored.) Mark this plan `Done` here and in `plans/_index.md`.

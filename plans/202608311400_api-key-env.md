# `api_key_env` — resolve API keys from an environment variable

**Status:** Done

Implements the `api_key_env` config option so API keys can be kept out of
committed config files. Adds a shared `resolve_api_key` helper in the module
base, wires both Deepgram modules to it, and switches the e2e harness to a
committed `tests-e2e/e2e.config.json` that names an env var.

Governs [specs/asr-module-interface.md](../specs/asr-module-interface.md) (the
`resolve_api_key` helper in `modules/base.py`),
[specs/deepgram-module.md](../specs/deepgram-module.md) (the `api_key_env`
field), and [specs/e2e-testing.md](../specs/e2e-testing.md) (credential source).

## Scope

- `src/asr_mcp/modules/base.py` — new `resolve_api_key(config, module_label)`:
  returns `config["api_key"]`, else the value of the env var named by
  `config["api_key_env"]`, else raises `ValueError`.
- `src/asr_mcp/modules/deepgram_v1.py`, `deepgram_v2.py` — validate via
  `resolve_api_key` instead of the direct `api_key` check.
- `tests/modules/test_base.py` — functional tests for `resolve_api_key`.
- `tests-e2e/e2e.config.json` — **new**, committed; `asr.api_key_env` names the
  env var (`DEEPGRAM_API_KEY`).
- `tests-e2e/helpers.py` — `load_api_key()` reads `e2e.config.json`, resolves the
  env var, and `pytest.skip`s when it is unset (so e2e cases skip cleanly
  without credentials).
- `specs/asr-module-interface.md`, `specs/deepgram-module.md`,
  `specs/e2e-testing.md` — document the field/helper and the new credential flow.
- `AGENTS.md` — live-testing section: keys live in `~/.zshrc`; the non-interactive
  shell doesn't source it, so run e2e under an interactive `zsh`.

## Steps

1. Add `resolve_api_key` to `modules/base.py` (imports `os`). Precedence:
   `api_key` (literal) → `api_key_env` (env var lookup, error if unset/empty) →
   error naming both options.
2. Point both Deepgram modules at it: `self._api_key = resolve_api_key(config,
   "deepgram_v1" / "deepgram_v2")`.
3. Add `tests/modules/test_base.py` cases: literal key wins; env var resolved;
   missing env var raises; neither present raises.
4. Add `tests-e2e/e2e.config.json` with `asr.type=deepgram_v1`,
   `api_key_env="DEEPGRAM_API_KEY"`, `model="nova-3"`.
5. Rewrite `helpers.load_api_key()` to read `e2e.config.json`, honour
   `api_key`/`api_key_env`, and `pytest.skip` when unresolved.
6. Update the three specs (`api_key_env` field in the Deepgram config tables and
   examples, the `resolve_api_key` helper in the module-interface spec, and the
   credential source in the e2e spec) and `AGENTS.md` (zshrc note + command).

## Verification

- `tests/modules/test_base.py` covers all four `resolve_api_key` branches.
- Full gate: `uv run ruff check .`, `uv run ruff format .`, `uv run pyright`,
  `uv run pytest tests/`.
- E2E remains opt-in: with `DEEPGRAM_API_KEY` unset the cases skip; run under an
  interactive zsh (`zsh -ic 'uv run pytest tests-e2e'`) to exercise them live.

# Kyutai local STT module (MLX + PyTorch backends)

**Status:** In progress

Implements `specs/kyutai-module.md` in full, plus the edits it forces on `specs/configuration.md` (a 24 kHz example), `specs/e2e-testing.md` (24 kHz fixtures + a second skip axis), and `specs/asr-module-interface.md` (the extras table). Delivers the first **local, on-device** ASR module: one registry key `kyutai` over two interchangeable backends (MLX on Apple Silicon, PyTorch elsewhere), finalizing on the model's semantic VAD head with a silence-timer fallback. It deliberately leaves out the Rust-server module, prompting, and word-level timestamps (all non-goals in the spec), and does **not** touch `specs/vad.md`'s `VadGate` — the two are orthogonal and `202609211000_vad-gate-and-finalize.md` follows independently.

## Design summary

The MLX and PyTorch inference loops differ only at model load and one `step()` call, so the module splits there: `KyutaiModule` (all shared behaviour) over a `KyutaiBackend` protocol with two implementations. The same seam is what lets the fast tier test the module against a scripted fake backend with **no Kyutai extra installed** — steps 3–5 below add real, functional coverage before a single line of `moshi` code exists.

Three concurrent pieces make up a running module: an async feed loop (audio queue → float32 → 1920-sample frames), a worker **thread** (frames → `backend.step()`, because the maths blocks), and an async emit loop (step results → accumulation → `on_utterance`). Keeping accumulation and finalization on the event loop means `on_utterance` is awaited normally and all the interesting logic stays single-threaded and testable.

## Steps

1. **Spike: measure the real-time factor, then settle the spec.** `uv sync --extra kyutai-mlx`, then write `scripts/benchmark_kyutai.py`: load `kyutai/stt-1b-en_fr-candle`, feed `tests-e2e/fixtures/sample_44100_theskyisblue.mp3` (read at 24 kHz via `sphn.read(path, sample_rate=24000)`) frame by frame, and report wall-clock per `step()` plus the overall RTF. **This is a gate, not a formality:** the whole backpressure design assumes RTF < 1. If the 1B model cannot keep up on this machine, stop and revise the spec (quantized MLX variants become mandatory rather than optional) before writing any module code. Record the measured RTF in the spec, resolve the open question, and promote `specs/kyutai-module.md` `Draft` → `Stable`. Also confirm here: that `-candle` weights load in MLX via `model.load_pytorch_weights(...)`, that `step_with_extra_heads` returns four heads with `vad_heads[2][0,0,0]` as the end-of-turn probability, and what `moshi_mlx` version is actually resolved (upstream's scripts pin 0.2.12; PyPI is at 0.3.0).

2. **Packaging** (`pyproject.toml`). Add the two extras exactly as specced — the `sys_platform == 'darwin' and platform_machine == 'arm64'` marker on `kyutai-mlx` is load-bearing, since `mlx` has no Linux wheels and an unmarked entry inside `all` would break `uv sync` there outright. Add both to `all`; add only `kyutai-mlx` to the `dev` group. Run `uv sync` and confirm `uv run python -c "import moshi_mlx"` works on this machine. Sanity-check the Linux path with `uv sync --python-platform linux --dry-run` (or equivalent) to prove `all` still resolves without mlx.

3. **Shared module** (`modules/kyutai.py`) — no `moshi` import anywhere in this file.
   - `@dataclass(frozen=True) class StepResult: text: str | None; end_of_turn_p: float | None`.
   - `class KyutaiBackend(Protocol)` with `SAMPLE_RATE`/`FRAME_SAMPLES` class vars, `has_vad` / `steps_remaining` properties, and `load()` / `step(frame) -> StepResult` / `reset()` / `close()`, all synchronous.
   - `class KyutaiModule(ASRModule)`: `SUPPORTED_SAMPLE_RATES = frozenset({24000})`, `SUPPORTED_CHANNELS = frozenset({1})`, `SUPPORTED_ENCODINGS = frozenset({"linear16"})`, defaults `24000 / 1 / "linear16"`.
   - `__init__`: validate every field per the spec (unknown `backend`; `max_steps > 0`; `0 < vad_threshold < 1`; `finalize_after_silence_s >= 0`; `lag_drop_s > lag_warn_s`), then resolve a **backend factory** — do not load. Take an optional `backend_factory` keyword for tests; when absent, resolve from `backend` (`"auto"` → `mlx` if `sys.platform == "darwin"` and `platform.machine() == "arm64"` and `moshi_mlx` is importable, else `torch`) and raise the spec's `ImportError` naming `kyutai-mlx` / `kyutai-torch` when the chosen one is unavailable. Use `importlib.util.find_spec` for the probe so nothing heavy is imported at construction.
   - `start(...)`: on first call only, create the backend and `await asyncio.to_thread(backend.load)` inside the standard 1/2/4/8 s backoff loop, draining `audio_queue` between attempts (reuse the `_drain_queue_for` shape from `deepgram_v2.py`). Then `on_connected(True)`, feed `stt_config.audio_silence_prefix_seconds` of zero frames, and run the three pieces described in the Design summary concurrently until stopped.
   - **Feed loop** (async): `audio_queue.get()` → append to a `bytearray` → while ≥ `FRAME_SAMPLES * 2` bytes, slice one frame, `np.frombuffer(f, "<i2").astype(np.float32) / 32768.0`, put on a `queue.Queue`. Carry the remainder. Racing `audio_queue.get()` against the stop event uses the same two-task `asyncio.wait(FIRST_COMPLETED)` pattern the Deepgram modules use, cancelling the loser in a `finally`.
   - **Worker thread**: blocking `frame_queue.get()` → `backend.step(frame)` → `loop.call_soon_threadsafe(result_queue.put_nowait, res)`. A `None` sentinel ends it. Wrap `step()` so an exception is marshalled to the emit loop rather than killing the thread silently.
   - **Emit loop** (async): consume `result_queue`; a non-`None` `text` appends to the accumulator and emits `SpeechUtterance(accumulated, is_final=False, confidence=None)`; finalize on either a **rising-edge** `end_of_turn_p > vad_threshold` (latch a `_vad_high` flag, clear it when the probability drops back under, exactly as upstream's `last_print_was_vad` does) or `steps_since_text * 0.08 >= finalize_after_silence_s`. **Drive the silence timer off the step count, not the wall clock** — one step is always 80 ms of audio, so this is an audio-time clock like the `fake` module's, which keeps the fast tests deterministic. A finalization with an empty accumulator emits nothing, matching the Deepgram modules.
   - **Step budget**: track `backend.steps_remaining`; at a finalization boundary, if it is below one utterance's worth (say 2× `finalize_after_silence_s` in steps), call `backend.reset()`. If it hits zero mid-utterance, force-finalize what is accumulated, `reset()`, and log a warning.
   - **Backpressure**: lag is `frame_queue.qsize() * 0.08`. Above `lag_warn_s`, log a warning (rate-limited). Above `lag_drop_s`, drop oldest frames until back to `lag_warn_s` and log at error level.
   - `stop()`: set the stop event, push the sentinel, join the worker with a timeout, `backend.reset()`, `on_connected(False)`. **Do not** drop the backend — `listen()` start/stops per call and reloading a 1B model each time would make it unusable.

4. **Registry + config.** Add `REGISTRY["kyutai"] = LazyModule("asr_engine.modules.kyutai:KyutaiModule")` (no `extra` — `kyutai.py` imports nothing third-party, and the module raises its own per-backend hint). Add the worked 24 kHz example to `config.example.json` and `specs/configuration.md`; note there that `engine.audio.sample_rate` must be `24000`, since the 16000 default would otherwise fail reconciliation at construction.

5. **Fast tests** (`tests/modules/test_kyutai.py`). Build a `ScriptedBackend` (a list of `StepResult`s, plus a configurable `steps_remaining`) injected via `backend_factory`, so the whole file runs with no Kyutai extra installed. Cover exactly the spec's list: re-blocking (including remainder carry and a partial trailing chunk that must *not* be emitted); s16→float32 scaling at the extremes; interim accumulation and padding-token suppression; VAD rising-edge finalization emitting **one** final across a sustained high run, with `confidence` carrying the probability; timer finalization firing at the configured audio time and *not* firing while text still arrives; empty-accumulator suppression; step-budget recycle at a boundary and force-finalize when exhausted mid-utterance; backpressure dropping oldest and keeping newest; lifecycle (`on_connected(True)` only after `load()` returns, `stop()` unblocks an idle `start()`, `stop()` keeps the backend); backend auto-resolution under a monkeypatched `sys.platform` / `platform.machine`; and one test per validation branch.

**Deviations from the steps above, and why:**

- **The VAD final is deferred by `audio_delay_seconds`** (step 3 had it fire on the rising edge). The step-1 measurements showed the head crossing the threshold *before* the utterance's last words arrive — the head tracks the audio, the text runs 0.5 s behind — so an immediate final truncated every utterance and re-emitted its tail as a stray second final. The edge now arms the final, emitted `ceil(delay / 0.08)` steps later. The latch clears on the probability falling, not on new text. See the spec's "Utterance semantics".
- **`KyutaiBackend` gained `audio_delay_s` and `silence_prefix_s`**, which the module needs for the deferral and the silence prefix and can only get from the repo's `stt_config`.
- **One persistent single-thread executor instead of a per-session thread + `asyncio.to_thread(load)`**: every backend call (`load`/`step`/`reset`/`close`) runs on the same thread for the backend's whole life, since MLX streams and PyTorch streaming state are thread-sensitive. The worker resets the backend as it leaves a session.
- **`stop()` awaits the teardown** rather than performing it: `ASREngine.stop()` cancels the `start()` task as soon as `module.stop()` returns, so `stop()` waits until `start()` has joined the worker.
- **Hard budget exhaustion is handled in the worker** (reset before the step, then a marker telling the emit loop to force-finalize), because a reset requested from the emit loop would queue behind frames that would already raise `reached max-steps`. The recycle margin is `max(2 × finalize_after_silence_s, max_steps // 10)`, and an **idle** stretch also counts as a boundary, which is what recycles an always-on session nobody speaks to.
- **The audio queue is drained while the model loads**, and a `step()` failure discards and reloads the backend on the backoff ladder (the analogue of a dropped socket). Neither was in the steps.
- **E2E:** `test_engine_streams` hard-coded 44.1 kHz, so `MODULES` rows gained a `ModuleAudio` (format + the two fixtures); `require_local_model` takes the module type and looks its env var up in `LOCAL_MODEL_OPT_IN_ENV`.
- **`config.kyutai.example.json` is a new file** rather than an edit to `config.example.json`, which can hold only one config and is what the READMEs `cp` for the Deepgram quick-start.
- **Fallout from the `sounddevice==0.5` pin**: pyright flagged `AudioCapture.list_devices()` under 0.5.0, fixed with an `Any` annotation. `moshi-mlx`'s pins also moved the dev lock back on numpy, pydantic, starlette, websockets and gradio (6.26 → 5.38 in the synced venv); all tiers pass on that set.
- **`_kyutai_torch.py` ships unverified**, as planned — never run, type-checked only under suppression. Flag it in the PR.
